Design Document: tpt-barcode (v2: tpt-math Integrated)
1. The Strategic Advantage
By building tpt-barcode on top of tpt-math, we achieve what no other Rust barcode library can:
True Zero-Allocation Scanning: Perspective correction (un-skewing a QR code from a photo) requires inverting a 3x3 matrix. tpt-math-linalg-fixed does this at compile-time known sizes with zero heap allocation, making it viable for embedded no_std IoT scanners.
Guaranteed Pure MIT Chain: tpt-math already enforces ADR-0007 (no Apache-2.0-only dependencies). By depending on it, tpt-barcode inherits this bulletproof legal posture.
No Bloat: We don’t pull in 50 transitive dependencies for a simple homography transform. We just pull in tpt-math-geometry.
2. Revised Workspace Architecture
We split the domain logic from the math logic. tpt-math handles the raw numbers; tpt-barcode handles the symbology rules.

tpt-barcode/
├── tpt-barcode-core/    # Symbology traits, GF(256), Reed-Solomon error correction
├── tpt-barcode-1d/      # 1D Symbologies (Code128, EAN-13, UPC-A, Code39)
├── tpt-barcode-2d/      # 2D Symbologies (QR, DataMatrix, PDF417) 
                         # ↳ Depends on: tpt-math-geometry, tpt-math-linalg-fixed
├── tpt-barcode-image/   # Image processing, SIMD binarization, edge detection
├── tpt-barcode-render/  # Output formatters (SVG, PNG, ANSI terminal)
└── tpt-barcode/         # The main facade crate (re-exports with feature flags)

3. How tpt-barcode Leverages tpt-math
Here is exactly how the existing tpt-math crates map to the barcode scanning pipeline:
A. Finder Pattern Detection (tpt-math-geometry)
When scanning an image, we first locate the three QR finder patterns (the squares in the corners).
We extract candidate points and use tpt-math-geometry to calculate distances and verify the 1:1:3:1:1 ratio of the bars.
We fit a bounding box or circle to the noisy pixel clusters using geometric projections.
B. Perspective Correction / Homography (tpt-math-linalg-fixed + tpt-math-geometry)
Once we have the 4 corner points of the skewed QR code, we need to map them to a flat 2D grid.
We construct a 3x3 Homography matrix. Because it’s 3x3, we use tpt-math-linalg-fixed::Matrix3.
We compute the inverse using the closed-form determinant/inverse methods in tpt-math-linalg-fixed. No heap allocation, no dynamic dispatch.
We use tpt-math-geometry projections to sample the pixel grid of the un-skewed image.
C. Error Correction (tpt-barcode-core)
This is the one piece we need to build from scratch.
While tpt-math handles general algebra, Barcode-specific Galois Field (GF(256)) arithmetic and Reed-Solomon polynomial division are highly specialized.
We will build this in tpt-barcode-core.
It will use tpt-math-numeric for the underlying scalar trait bounds, ensuring it remains no_std compatible.
We will use compile-time const arrays for the GF(256) Exp/Log lookup tables to guarantee zero runtime initialization cost.
4. The Target API (Showcasing the Integration)
The API should feel seamless, hiding the complex math behind intuitive builders.

use tpt_barcode::prelude::*;
use tpt_math_geometry::Point2;

// --- GENERATION ---
let qr = tpt_barcode::qr::encode("https://github.com/tpt-solutions", EcLevel::M)?;
let svg = qr.render().svg().module_size(4).build();

// --- SCANNING ---
// Load image (using the `image` crate, which is MIT/Apache dual)
let img = image::open("skewed_qr.jpg")?.into_luma8();

// Scan with robust perspective correction
let results = tpt_barcode::scan(&img)
    .formats(&[Format::Qr])
    .try_harder(true) // Enables tpt-math-geometry homography un-skewing
    .execute()?;

for result in results {
    println!("Decoded: {} (Format: {:?})", result.text(), result.format());
    
    // The result can even expose the geometric bounds found in the image
    let corners: [Point2<f32>; 4] = result.bounding_box();
    println!("Found at corners: {:?}", corners);
}

5. Execution Roadmap (Adjusted for Reality)
Since tpt-math is already solid, we can move much faster.
Phase 1: The Mathematical Heart (Weeks 1-2)
Goal: Build tpt-barcode-core with GF(256) and Reed-Solomon.
Tasks:
Implement GF(256) addition/multiplication/inversion with const lookup tables.
Implement Reed-Solomon encoder/decoder (polynomial division).
Write exhaustive unit tests against known QR code payloads.
Why first? You can’t generate or decode a single QR code without this. It’s the foundational domain logic.
Phase 2: Pure Rust Generation (Weeks 3-4)
Goal: tpt-barcode-2d (QR) and tpt-barcode-render.
Tasks:
Implement QR mode indicator, character counting, and bit stream packing.
Integrate with tpt-barcode-core for error correction codewords.
Build the mask pattern evaluator (penalty rules) to find the optimal mask.
Output to SVG (trivial) and PNG (via image crate).
Phase 3: The Computer Vision Scanner (Weeks 5-8)
Goal: tpt-barcode-image and QR decoding.
Tasks:
Implement adaptive thresholding (binarization) for robust image prep.
Implement finder pattern detection.
The Magic Moment: Wire up tpt-math-linalg-fixed and tpt-math-geometry to compute the homography and sample the un-skewed grid.
Feed the sampled bits into the Phase 1 Reed-Solomon decoder.
